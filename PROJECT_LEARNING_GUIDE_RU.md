# Character Archive: учебный разбор проекта

Этот файл нужен не только для чтения. Открой сайт через Live Server, поставь браузер на одну половину экрана, VS Code — на другую, меняй по одному значению и сразу наблюдай результат.

Главное правило обучения: **сначала предположи, что изменится, затем меняй код и только после этого смотри в браузер**. Так CSS перестаёт быть набором случайных чисел.

---

## 1. Ментальная модель сайта

У проекта три самостоятельные страницы:

1. `index.html` в корне — хаб, из которого выбирают героя.
2. `characters/ichika/index.html` — страница Ичики.
3. `characters/jack/index.html` — страница Джека.

Браузер читает HTML сверху вниз. HTML отвечает за **смысл и структуру**, CSS — за **вид и расположение**, JavaScript — за **поведение, которое зависит от действий пользователя**.

Полезная аналогия:

- HTML — комнаты и двери дома;
- CSS — размеры, цвета, мебель и освещение;
- JavaScript — выключатели, лифт и автоматические двери.

2. Где искать скорость анимации?

## 2. Как связаны папки и относительные пути

На главной странице ссылка выглядит так:

```html
href="characters/ichika/index.html"
```

Браузер начинает путь от текущего файла и идёт внутрь папок `characters`, затем `ichika`.

На странице Ичики ссылка назад выглядит так:

```html
href="../../index.html"
```

Каждые `../` означают «подняться на одну папку выше»:

- первое `../` ведёт из `ichika` в `characters`;
- второе `../` ведёт из `characters` в корень проекта;
- затем браузер открывает корневой `index.html`.

### Эксперимент

Временно убери один `../`, нажми ссылку Archive и посмотри адрес ошибки. После эксперимента верни путь. Так легче понять, почему сайт иногда работает из одного файла и ломается после деплоя.

## 3. Структура HTML главного хаба

Упрощённая схема:

```text
body
├── skip-link
├── header.site-header
├── main.archive
│   ├── a.portal.portal--ichika
│   └── a.portal.portal--jack
└── footer.site-footer
```

### Почему вся карточка — ссылка

Элемент `<a class="portal">` содержит фон, имя, описание и изображение. Поэтому вся большая область кликабельна. Это удобнее, чем маленькая кнопка внутри карточки, и работает с клавиатуры без дополнительного JavaScript.

### Зачем нужны классы-модификаторы

У обеих карточек есть общий класс `.portal`, поэтому размеры и анимации описаны один раз. Классы `.portal--ichika` и `.portal--jack` меняют только характерные цвета и изображения.

Такой принцип можно сформулировать так:

- общий класс описывает семейство компонентов;
- класс-модификатор описывает конкретный вариант.

### Что означают семантические элементы

- `<header>` — верхняя служебная часть страницы;
- `<nav>` — блок основных переходов;
- `<main>` — уникальное главное содержимое;
- `<section>` — законченный смысловой раздел;
- `<footer>` — нижняя информация;
- `<h1>` — главный заголовок страницы;
- `<figure>` — самостоятельное изображение или иллюстрация;
- `<dialog>` — встроенное модальное окно;
- `<dl>`, `<dt>`, `<dd>` — список терминов и значений, например фактов о герое.

### Практическое задание

Добавь в каждую карточку хаба короткую строку с годом появления героя. Сначала сделай правильный HTML без стилей. Затем оформи новый класс в CSS.

## 4. Контейнеры: что это на самом деле

«Контейнер» — не отдельный HTML-тег. Это обычный элемент, который содержит другие элементы. Чаще всего используют `<div>`, но семантический `<section>` или `<main>` тоже являются контейнерами.

У каждого видимого элемента есть прямоугольная коробка:

```text
margin → border → padding → content
```

- `content` — текст или картинка;
- `padding` — внутреннее расстояние от содержимого до рамки;
- `border` — рамка;
- `margin` — внешнее расстояние до соседей.

В проекте везде задано:

```css
box-sizing: border-box;
```

Поэтому указанная `width` уже включает padding и border. Это делает размеры предсказуемыми.

### Эксперимент

Найди `.brand__mark` в корневом `styles.css`.

1. Измени `width: 2.5rem` на `5rem`.
2. Добавь `padding: 1rem`.
3. Удали `box-sizing: border-box` только у этого элемента.

Сравни три состояния и верни исходные значения.

## 5. Flexbox на примере двух порталов

У `.archive` задано:

```css
display: flex;
```

Это превращает прямых детей в элементы одного ряда. У каждой `.portal` есть:

```css
flex: 1 1 50%;
```

Три числа означают:

1. `flex-grow: 1` — элемент может занять свободное место;
2. `flex-shrink: 1` — элемент может сжиматься;
3. `flex-basis: 50%` — начальный размер равен половине контейнера.

При наведении меняется `flex-grow`, поэтому выбранная половина плавно расширяется.

На мобильном экране медиазапрос задаёт:

```css
flex-direction: column;
```

Теперь главная ось идёт сверху вниз, и порталы стоят друг под другом.

### Эксперимент

Поставь `.archive { flex-direction: column; }` вне медиазапроса. Затем попробуй `row-reverse`. Перед каждым изменением предскажи расположение карточек.

## 6. Размеры: px, rem, %, vw, vh и clamp()

- `px` — фиксированный CSS-пиксель;
- `rem` — размер относительно шрифта корневого `<html>`;
- `%` — размер относительно родителя;
- `vw` — процент ширины окна;
- `vh` и `svh` — процент высоты окна;
- `clamp(min, preferred, max)` — значение, которое растёт, но не выходит за границы.

Пример:

```css
font-size: clamp(5.5rem, 10vw, 11.5rem);
```

Имя героя стремится занимать `10vw`, но не становится меньше `5.5rem` и больше `11.5rem`.

`100svh` используется для полного экрана. Единица `svh` лучше ведёт себя на телефонах, где панель браузера меняет доступную высоту.

### Вопрос

## 7. Position и система слоёв

У `.portal` стоит `position: relative`. Это создаёт систему координат для вложенных элементов с `position: absolute`.

Внутри карточки элементы занимают одно пространство и складываются слоями:

```text
scene → shade → number → figure → content
```

Порядок контролирует `z-index`. `isolation: isolate` не позволяет отрицательным слоям случайно уйти за пределы всей страницы.

Основные значения `position`:

- `static` — обычный поток документа;
- `relative` — элемент остаётся в потоке и может стать опорой;
- `absolute` — элемент вынимается из потока и позиционируется относительно ближайшей опоры;
- `fixed` — привязан к окну браузера;
- `sticky` — ведёт себя обычно, а после порога «прилипает».

### Эксперимент

У `.portal__content` временно убери `position: absolute` через правило `position: static`. Посмотри, как содержимое возвращается в обычный поток.

## 8. Фоны, изображения и затемнение

В хабе основная фотография назначена как `background-image`, потому что она декоративная и должна заполнять всю область через `background-size: cover`.

Прозрачный персонаж — настоящий `<img>`, потому что для него нужны `object-fit: contain`, отдельный слой и независимое движение.

Разница:

- `cover` заполняет контейнер и может обрезать края;
- `contain` показывает изображение целиком и может оставить свободное место.

Затемнение сделано отдельным градиентным слоем. Это лучше, чем уменьшать `opacity` у всей карточки: иначе побледнеют и текст, и персонаж.

### Практическое задание

Поменяй `background-position` сначала на `left center`, затем на `80% center`. Подбери кадрирование для ширины 1440 px и для ультраширокого экрана.

## 9. CSS-переменные и палитры

Переменная объявляется так:

```css
--accent: #d88fae;
```

Используется так:

```css
color: var(--accent);
```

В `.portal--jack` значение переменной переопределяется. Все вложенные элементы автоматически получают новый акцент. Поэтому не нужно искать каждую кнопку и линию отдельно.

В страницах героев глобальные цвета находятся в `:root`. Это первая точка, куда стоит идти при создании новой темы.

### Эксперимент

Измени только `--accent-soft` у Джека на ярко-синий. Найди все места, которые поменялись сами. Затем верни золотистый цвет.

## 10. Border, border-radius и тени

- `border: 1px solid color` задаёт толщину, стиль и цвет рамки;
- `border-radius` скругляет углы;
- `border-radius: 50%` превращает квадрат в круг;
- `border-radius: 999px` создаёт форму капсулы;
- `box-shadow` рисует тень вокруг коробки;
- `filter: drop-shadow()` учитывает прозрачную форму PNG/WebP, а не только прямоугольник.

Именно поэтому для вырезанной фигуры используется `drop-shadow`, а для панелей диалога удобен `box-shadow`.

## 11. Transition, transform и «дешёвые» анимации

`transition` описывает переход между старым и новым состоянием:

```css
transition: transform 1s cubic-bezier(...);
```

`transform` меняет визуальное положение, масштаб или поворот:

- `translateX()` — движение по горизонтали;
- `translateY()` — движение по вертикали;
- `translate3d(x, y, 0)` — движение с хорошей производительностью;
- `scale()` — масштаб;
- `rotate()` — поворот.

Старайся анимировать прежде всего `transform` и `opacity`: браузер обычно делает это плавнее, чем анимацию `width`, `left` или сложных теней.

Кривая `cubic-bezier(0.22, 1, 0.36, 1)` даёт быстрое начало и мягкую остановку. Она создаёт ощущение редакционной, а не механической анимации.

## 12. Как работает JavaScript хаба

Скрипт получает все порталы:

```js
document.querySelectorAll("[data-portal]")
```

`data-portal` — пользовательский HTML-атрибут. Он удобен как устойчивый крючок для поведения: CSS-класс можно переименовать ради дизайна, не ломая скрипт.

На событии `pointermove` код:

1. получает размеры карточки через `getBoundingClientRect()`;
2. вычисляет положение курсора от `-0.5` до `0.5`;
3. записывает результат в CSS-переменные через `style.setProperty()`;
4. CSS использует переменные в `transform`.

JavaScript здесь не рисует анимацию кадр за кадром. Он только передаёт CSS небольшие координаты.

Проверки `matchMedia()` отключают эффект на сенсорных устройствах и при включённом `prefers-reduced-motion`.

### Практическое задание

Найди множитель `18` у `--figure-x`.

1. Поставь `40` и оцени эффект.
2. Поставь `-18` и посмотри, как меняется направление.
3. Верни `18`, потому что небольшая глубина меньше отвлекает от выбора.

## 13. Галерея без видимого конца

Каждая строка начинается с одного `.gallery-group`. Скрипт клонирует группу и добавляет копию рядом. CSS двигает трек ровно на половину его длины. В момент повторения конец первой группы совпадает с началом второй, поэтому скачок незаметен.

Первая строка использует анимацию `gallery-forward`, вторая — `gallery-reverse`. Разные `animation-duration` не дают двум рядам двигаться как единый жёсткий блок.

`animation-delay` может быть отрицательным. Это означает, что анимация при открытии выглядит так, будто она уже некоторое время выполнялась.

## 14. Как работает About

HTML-элемент `<dialog>` умеет открываться поверх страницы. Скрипт вызывает `showModal()`, обновляет `aria-expanded`, а при закрытии возвращает фокус на кнопку About.

Это важная деталь доступности: человек, который управляет сайтом клавиатурой, не должен после закрытия терять своё место.

Диалог закрывается:

- кнопкой с крестиком;
- клавишей Escape — это встроенное поведение `<dialog>`;
- кликом по затемнённой области вокруг содержимого.

### Практическое задание

Открой About без мыши: несколько раз нажми Tab, затем Enter, потом Escape. Убедись, что фокус вернулся на About.

## 15. Адаптивность

Медиазапрос:

```css
@media (max-width: 900px) { ... }
```

применяет правила, когда ширина окна не больше 900 px. В проекте медиазапросы не создают второй сайт — они меняют только те свойства, которые перестают работать на маленьком экране.

На мобильном хабе:

- порталы складываются вертикально;
- огромный декоративный номер скрывается;
- описание скрывается, чтобы оставить ясную иерархию;
- фиксированная высота заменяется прокруткой.

### Как тестировать

Проверь минимум эти ширины:

- 3440 × 1440 — ультраширокий монитор;
- 1440 × 900 — обычный ноутбук;
- 768 × 1024 — планшет;
- 390 × 844 — телефон.

Не проверяй только точку медиазапроса. Особенно полезны ширины 899 и 901 px.

## 16. Доступность и prefers-reduced-motion

В проекте есть:

- ссылка Skip to content, видимая при фокусе;
- понятные `aria-label`;
- `alt` у содержательных изображений и пустой `alt` у декоративных;
- `:focus-visible` для клавиатуры;
- семантические заголовки;
- нативный `<dialog>`;
- режим сокращённой анимации.

Правило `prefers-reduced-motion: reduce` почти обнуляет длительность анимаций. Это не «лишняя опция», а способ не вызывать дискомфорт у части посетителей.

## 17. Производительность изображений

Главные изображения загружаются сразу, а галерея использует:

```html
loading="lazy" decoding="async"
```

- `loading="lazy"` откладывает загрузку изображения до приближения к экрану;
- `decoding="async"` разрешает браузеру декодировать изображение, не задерживая остальную страницу;
- `fetchpriority="high"` сообщает, что главный портрет особенно важен.

Для будущей оптимизации:

1. храни фотографии в WebP или AVIF;
2. не увеличивай маленькое изображение только через CSS;
3. для разных экранов добавь `srcset`;
4. проверяй визуальное качество после сжатия, а не ориентируйся только на размер файла.

## 18. Как добавить третьего героя самостоятельно

Порядок работы:

1. Создай новую папку в `characters/`.
2. Скопируй ближайшую по структуре страницу героя.
3. Сначала замени тексты, `title`, description и About.
4. Затем замени все изображения и проверь пути.
5. После этого определи палитру в `:root`.
6. Добавь портал на главную страницу.
7. Настрой кадрирование и только потом анимации.
8. Проверь мобильную версию, клавиатуру и сокращённое движение.

Не начинай с десяти новых эффектов. Сначала добейся правильной композиции в статичном состоянии.

### Контрольный проект

Добавь тестовую карточку без отдельной страницы:

- выбери героя;
- определи четыре цвета;
- добавь портал с пометкой `Coming soon`;
- сделай так, чтобы ссылка не открывала несуществующий файл;
- объясни, почему выбранная палитра соответствует образу.

## 19. Git как история обучения

Хороший коммит отвечает на вопрос: «Какой законченный шаг появился?»

В этом проекте история разделена так:

1. начальная структура и изображения;
2. интерактивный хаб;
3. интеграция двух архивов;
4. документация и финальная проверка.

Перед коммитом:

1. посмотри изменённые файлы;
2. открой сайт;
3. проверь консоль браузера;
4. убедись, что не добавил пароли, токены и временные файлы;
5. сформулируй сообщение в повелительном стиле: `Add`, `Fix`, `Refine`, `Document`.

Git одного проекта не мешает другому: каждая папка с собственной `.git` хранит независимую историю. Глобальные имя и email могут быть общими, но ветки, коммиты и удалённые адреса принадлежат конкретному репозиторию.

8. Длительные движения практически отключаются.
9. По пути `../../index.html`.
10. Изменённые файлы, внешний вид, консоль, отсутствие секретов и мусора.

</details>

## 21. Как учиться дальше

После того как уверенно объяснишь текущий проект, двигайся в таком порядке:

1. CSS Grid и более сложные сетки.
2. Формы и их доступность.
3. Асинхронный JavaScript и загрузка JSON.
4. Компонентное мышление без фреймворка.
5. Затем — любой фреймворк, например React или Vue.

Цель этого проекта не в том, чтобы запомнить каждое свойство. Цель — научиться раскладывать дизайн на контейнеры, связи, слои, состояния и адаптивные правила.
